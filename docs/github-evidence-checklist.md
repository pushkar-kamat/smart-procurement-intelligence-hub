# GitHub and submission evidence checklist
- [ ] Initialize your own repository and record the generated baseline honestly.
- [ ] Create issues from backlog with owners and acceptance criteria.
- [ ] Each member creates genuine feature/fix branches and commits.
- [ ] Open PRs; the other member reviews actual changes.
- [ ] Capture successful CI run URL + commit (YAML alone is not evidence).
- [ ] Capture container build/run and clean setup logs.
- [ ] Attach actual pip/npm audit output and remediation notes.
- [ ] Capture deployed health, safe logs and metrics.
- [ ] Run stakeholder acceptance and manual baseline timing.
- [ ] Add actual screenshots, report, presentation and 5–8 minute video.
- [ ] Fill authentic individual logs and technical ownership evidence.
- [ ] Tag a tested release; note unresolved limitations.

No fake commits, reviews, work hours, deployment links or interview quotes are included.
