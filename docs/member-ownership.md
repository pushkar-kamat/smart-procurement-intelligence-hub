# Balanced two-member ownership
Assignments describe intended technical ownership and review; they do not claim either student authored the generated ZIP or completed hours already.

| Member | Vertical modules | Required hands-on work |
|---|---|---|
| 1 | Requisitions; vendor master/invitations; approvals; PO; price anomaly | React screens, API/services, DB/migrations, regression tests, explanations; Docker/backend deployment lead |
| 2 | Quotation entry/upload; comparison; vendor risk; delivery/invoice; audit | React screens, API/services, DB/migrations, regression tests, explanations; CI/frontend deployment/observability lead |
| Shared | Auth/RBAC, architecture/contracts, integration, security, evaluation, demo | Pair-review identity/state boundaries, run full acceptance and baseline, cross-review PRs, maintain real evidence |

Each member must understand and demonstrate their feature from UI to database. Import the generated baseline honestly, then create real issue-linked changes and reviews. Do not split as frontend person/backend person. Portfolio effort minimum is 100 hours per student; document actual work and clarify the compressed schedule with your guide rather than inventing hours.
